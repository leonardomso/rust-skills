# macro-pin-impl-crate

> Pin a companion proc-macro crate to your crate's exact version with `=x.y.z`

## Why It Matters

Code generated by a proc macro calls into the facade crate that re-exports it. If the macro crate and the facade are on different versions, the generated code can reference items that do not exist or have changed, and the compile errors point into macro output that is hard to read. Pinning both halves to one exact version, and publishing them together, makes that mismatch impossible. This applies to macro crates that exist only to serve one library, not to independently used macro libraries.

## Bad

```toml
# my_lib/Cargo.toml
[dependencies]
# Any 1.x release is accepted; a newer macro may emit code this my_lib does not have
my_lib_macros = "1"
```

## Good

```toml
# my_lib/Cargo.toml (version = "1.2.3")
[package]
name = "my_lib"
version = "1.2.3"

[dependencies]
# Exact pin: macro and library always match
my_lib_macros = { version = "=1.2.3", path = "../my_lib_macros" }
```

```toml
# my_lib_macros/Cargo.toml
[package]
name = "my_lib_macros"
version = "1.2.3"
```

Release both crates together with the same version number, for example with workspace version inheritance.
